**Staging.** Fixtures were staged answer-stripped outside the repository,
one copy per run: committed files only (`git archive`), both key files
deleted, and every `violation` line removed case-insensitively. Each copy
was checked with `grep -ri violation` and was clean
([`scoring/stage.sh`](v0.12.0/scoring/stage.sh)). The strip removed lines
only from the JS broken fixture's sources (its inline annotations); the
three clean variants are byte-identical to what is committed. This is the
first harness run with the `test-honesty` fixture (#486).

**Dispatch.** Every agent ran on Claude Opus 5.5 and read the checkout's
skill file directly, with the plugin root at the worktree:
- nine blind auditors;
- six remediators over three runs;
- one dogfood auditor;
- one showcase auditor (#576).

The blind auditors got the plain prompt from `evals/*/prompt.md` and the
declared architecture from `AUDIT-EXPECTATIONS.md` step 3 verbatim. For
`test-honesty` that is its own declaration.

**Scoring.** Each run's delivered message was taken from its transcript by
script and never retyped (#585, owner decision): the message of its
`SubagentHandback`, the text the orchestrator received
([`scoring/extract.py`](v0.12.0/scoring/extract.py)). The delivered
messages are committed in [`v0.12.0/reports/`](v0.12.0/reports/),
unchanged except that local paths are replaced by placeholders
(`<harness>`, `<tmp>`, `<home>`), and the checker ran on those files.
The transcripts themselves are not committed: they hold local paths and
every tool call's output. So the verdicts read from them (requirement 1's
timing, requirement 2's diffs, the step numbers and read times below)
cannot be re-derived from the repository alone. The scoring scripts are
committed in [`v0.12.0/scoring/`](v0.12.0/scoring/), with local paths as
placeholders, and so is their printed output for every remediator
([`scoring/outputs.txt`](v0.12.0/scoring/outputs.txt)): positions, tool
names and counts, with no transcript content. The scoring rules are
`AUDIT-EXPECTATIONS.md` and `REMEDIATE-EXPECTATIONS.md` as committed at the
base, fixed before any result was read.

**What changed between runs.**
- **The first fix (#589, PR #592).** Step 1 said to print the plan "as its
  own message, before any tool call that changes a file under remediation",
  and to repeat it below the record. That changed nothing about when the
  plan appeared, and its heading wording, "say it was printed before the
  first edit only if it was", was repeated as a false claim by both re-run
  remediators.
- **The second fix (owner decision: option A, #589, PR #600).** The plan
  became an action: a tool call of its own writes the plan table to a file
  outside the code under remediation. It must complete before anything
  changes the tree. The final message repeats the table with no timing
  claim. Both runs after it passed requirement 1.

(recorded on #589):

  PASS. A first scoring of rem-3 and rem-4 marked requirement 2 PASS without
  checking where the diffs were. That was corrected before the ruling, and
  their verdicts, FAIL on requirement 1, do not change.
- **Requirement 4 (rem-5).** It stated the gate as blocked in prose,
  naming three honest ways out, and left the flag untouched, but its record
