# plumb-line 0.12.1 — twins and tests tidy

plumb-line 0.12.1 is a patch. It pays the parity and test debts that
v0.12.0's self-audit and review found.

The JavaScript constructors now refuse an off-ladder value with a
`RangeError`, matching Python's `ValueError`, and both conformance runners
require their language's type. Code that checks for a plain `Error` may
break; match `RangeError` or the message. The JS runner can no longer be
crashed by a port that throws `null`. Python's audit names the taint flag
`derivedFromMock`, as JS always did. Two tests now prove what their names
said they proved.

PARITY.md had counted differences between the twins from a probe nobody had
committed. A probe is now in the repository, with a test holding the file to
its output: 34 of its 224 inputs differ in form, none in outcome.

The hooks' check for case aliases of `main` now ignores accent encoding, as
a probe showed macOS's filesystem does; it did not, so an accented protected
name could be reached by spelling it differently. Each twin also treats a
character too new for its runtime as matching any one character, so the
letters that first split the twins now block in both. Two differences
through very new Unicode remain. One fails open when a protected name holds
such a character, and the committed sweep tripled its measured reach. Both
are tracked ([#642](https://github.com/slopstopper/plumb-line/issues/642)).

The audit and remediate skills did not change, so neither validation was
re-run; v0.12.0's results stand. The self-audit of this release found eight
findings, including a test claimed to exist that did not, and figures typed
into the same file this release had just fixed for that reason. Seven are
fixed; one is tracked in #642.
