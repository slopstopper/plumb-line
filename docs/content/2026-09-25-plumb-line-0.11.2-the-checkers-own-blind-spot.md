# plumb-line 0.11.2 — the checker's own blind spot

plumb-line 0.11.2 is out on npm, PyPI, and the Claude Code marketplace. It
is a patch: eight fixes, each one an `audit-deferral` issue filed while an
earlier release was being built or audited, plus a ninth that its own
release harness found. Two of them make a tool refuse something it used to
accept, and the CHANGELOG marks both as stricter; a third renames a lint
site, so adopters who pinned one re-pin once.

The largest change is to the audit report's contract. The audit skill has
long said its omission-pass table is required: one row per
output-producing unit, one column per question, so that a missing lineage
field cannot hide behind a present provenance string. The format checker
never looked for the table, so a report without one could still carry
`format-validation: clean`. The checker now requires it, with the question
columns in order, no blank cells, and no empty table; a scope with nothing
to enumerate says so on a line of its own. The one committed report the
README quotes had no table, so it was replaced by a fresh blind audit of
the same demo under the updated skill. That report has nine findings, and
the README now says exactly how they map onto the demo's answer key,
including the one filed under a different principle than the key gives.

Two smaller fixes turned out to be covering larger problems. The issue
about the conformance scripts asked for their duplicated case-running
logic to be merged before it drifted. It had already drifted:
`report.mjs`, the script that decides whether an implementation earns the
conformance badge, ignored the expected lineage ids, so an implementation
with wrong step ids would have passed it. The two reference
implementations were always checked by their own test suites. Both scripts
now share one runner, which fails any case field or case kind it does not
interpret; the Python runners carry the same guard. The issue about the Python HTTP adapter being named
`http.py`, which shadows the standard library's `http` package, looked
hypothetical. It was already costing a test: one continuous-integration
step had skipped the fit-map example for `requests` on every run since
2026-09-10, when another test suite joining that step put `http.py` ahead
of the standard library. The file
is now `http_adapter.py`, the old import path still works as an alias
through 0.x, and that step now fails if the example skips.

The rest are smaller. SPEC §4 said a step id hashes the confidence score as a JSON
number, while both implementations hash its IEEE-754 bytes as hex, so a
port written from the spec would have produced different ids. The spec now
says what the code does and carries two worked examples that a test checks
against both languages. A destructured export's site name no longer
changes when the pattern is reformatted. The trigger-check harness records
its probe timeout and turn cap, and its docs no longer claim that a re-run
reproduces the rates. The worked baseline example now fails on drift, and
the ratchet fixtures' claim to be byte-identical to what `update` writes is
now tested.

Before merge, three independent reviewers read the change with different
briefs. None found a critical problem. Two of them found the same hole in
the new omission-table rule: a report that placed the omission table
before a malformed findings table, and said "No findings.", passed. Another
showed that the test meant to keep the skill and the checker in step never
read the checker; cutting the checker's column list in half left every
checker test green. Both were fixed before merge.

The release harness then ran six blind auditors. Every planted violation
was found in every run, including the missing-lineage case in both Python
runs, and both clean fixtures came back with no confirmed violations. All
six auditors also hit the same format failure on their first try: they
wrote the principle glossary inside a code fence, as the skill's own
example does, and the checker rejected it. The 0.11.1 record logged the
same failure as a wobble in the skill's output. The cause was in the
checker, which stripped part of the fence while masking inline code and
then blanked the whole glossary. It was fixed before the tag, with tests,
and every stored report that passed before still passes.

The self-audit of the release diff found five findings, one violation and
four needs-review. The violation was the audit skill still describing its
report as four parts in three places after the change made it five; that
and a comment that sent readers to PARITY.md for a note PARITY.md did not
contain were fixed in the release. Three are deferred as tracked issues, among them the question
of whether the report format should have moved to v4 when it gained a
required part.
