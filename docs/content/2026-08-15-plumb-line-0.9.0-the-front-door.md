# plumb-line 0.9.0 — the front door

plumb-line 0.9.0 is out on npm, PyPI, and the Claude Code marketplace. Real
user feedback came in. The skills were easy to adopt, the primitives were
not. It was unclear what to use them on and when to implement them into your
codebase.

That answer is now a skill. `plumb-line-adopt` inspects your repository and
says which parts fit and what to run first. It routes from a
[fit map](../../reference/fit-map.md) with four worked codebase profiles and
one anti-profile. If your codebase does not need provenance envelopes, it
says so and stops.

Two details from the build are worth recording.

The fit map's code examples run in CI. An independent review of the first
version found three snippets that crashed; they had been verified by import,
not by execution. A test now extracts every Python snippet from the doc and
runs it against the library, and a companion test fails if any snippet
escapes the guard. The examples are claims like any other, so they now have
a test.

The Node floor rose from 16 to 20. The old floor was a claim CI never
tested, and it was partly false: the HTTP subpath needs Node 18. Raising the
floor to the version CI exercises was the only honest fix, so the supported
floor is now the tested floor.

Before the tag, six blind auditors re-validated the audit skill against the
planted-violation fixtures: 6/6 pass, recorded in
[validation-results.md](../validation-results.md). The self-audit of our own
release diff found two findings; one fixed before the tag, one deferred as a
tracked issue.
