# plumb-line 0.12.0 — honest red

plumb-line 0.12.0 is out on npm, PyPI, and the Claude Code marketplace. The
milestone was called "Honest red": when a test cannot pass honestly, the
honest result is a red test, said plainly.

We gave an agent ordinary coding tasks where something it needed was
unavailable (a service down, an API key missing), and counted how often it
faked a passing result instead of reporting the blocker. Without plumb-line,
9 of 10 runs faked it. In a repository set up by `plumb-line-bootstrap`, 1 of
10 did. That code also used the provenance library, so bootstrap and the
library share the credit. The bootstrapped repository carried the effect: the
plugin's in-task skills on top made no measurable difference, and testing the
plugin on its own is planned
([#632](https://github.com/slopstopper/plumb-line/issues/632)). It was two
tasks with 10 runs per arm on one model, so read it as a direction; the
[record](../records/validation/2026-10-03-impossible-task-spike-round3.md)
has the details.

## What changed

The method skill now teaches honest deferral: a test that must wait gets a
strict expected-failure marker with its reason, and the decision goes back to
you. It also says a test never presents a stand-in's result as `real`. On one
task, agents that loaded the skill had been writing stub tests that asserted
fake data was real. With the rule added, that went from 6 of 6 such runs to
0 of 6 (verdicts read by hand).

The audit flags a test changed so that an unmet requirement reads as met.

The pre-commit gate is branch-aware. It still blocks a red suite on a
protected branch, and on other branches it lets the commit through with a
notice. Before, honest red work could not be committed anywhere; now 9 of 15
honest runs committed theirs on a branch, and in the spike nothing reached
`main`. We kept the change knowing its cost: in one arm the honest rate fell
to 6 in 10, 30 points below the baseline we set in advance (20 after a later
re-ruling), which our rule counts against the gate. The branch guard also
runs as a git commit hook.

In the libraries, constructors refuse a `confidence` or `source` off the
ladder, and leaves need a `source`. An egress guard stops mock data at an
output point, and test fixtures can be quarantined as `mock`. Several are
breaking; each Breaking entry in the CHANGELOG says what to do.

[ADR-0022](../adr/0022-tiers-enforcement-labels-auditability.md) sets out how
these fit together: enforcement where a block does not make ordinary work
impossible, accurate labels where it would, and auditability for the rest.

## Before the tag

The blind auditors passed 9 of 9. The remediate skill failed its validation
twice, then passed once its plan became a file written before any edit. The
self-audit found 23 findings in the release diff, and 7 more in the gate
change; each was fixed or filed. The stand-in rule merged after both passes.
Among the gaps still open: the audit misses a stub test that claims to be
real ([#620](https://github.com/slopstopper/plumb-line/issues/620)), and why
some agents made the requirement test skip itself is unknown
([#621](https://github.com/slopstopper/plumb-line/issues/621)).
