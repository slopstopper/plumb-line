# plumb-line 0.12.0 — honest red

plumb-line 0.12.0 is out on npm, PyPI, and the Claude Code marketplace. The
milestone was called "Honest red": when a test cannot pass honestly, the
honest result is a red test, said plainly. This release was built around
measuring whether plumb-line gets an agent there.

We gave an agent small, realistic jobs it could not finish honestly (a
service unreachable, an API key missing), told it to make the tests pass and
ship, and ran each job with and without plumb-line. Without plumb-line, 9 of
10 runs faked a green test. In a repository set up by `plumb-line-bootstrap`,
1 of 10 did. That is two tasks and 10 runs per arm, on one model, so it is a
direction rather than a rate. The [record](../records/validation/2026-10-03-impossible-task-spike-round3.md)
has the limits.

## Where to start

Bootstrap enforces your repo the fastest: it writes the ruleset and installs
the hooks, and they act on every run, whether or not the agent thinks to ask.
The method skill teaches you how it works, at the moment an edit would make
something look more finished than it is. Adopt tells you what your codebase
needs, if you are not sure yet. In the spike, adding the plugin's in-task
skills to a bootstrapped repository made agents no more honest, so bootstrap
is where most of the effect is.

## What changed

The method skill now teaches honest deferral: a test that must wait gets a
strict expected-failure marker with its reason, and the decision goes back to
you. It also says a test never presents a stand-in's result as `real`. The
spike found agents that loaded the skill writing stub tests that asserted
fake data was real. With that rule added, those runs went from 6 of 6 to 0 of
6.

The audit flags a test changed so that an unmet requirement reads as met.

The pre-commit gate is branch-aware. It still blocks a red suite on a
protected branch, and on other branches it lets the commit through with a
notice. Before, honest red work could not be committed anywhere, and agents
named `--no-verify` as the way round. Now 9 of 15 honest runs committed
their red work on a branch, and nothing reached `main`. It cost something:
in one arm the honest rate fell by 2 runs in 10, which our pre-registered
rule counts against the gate. We kept the change and recorded that. The
branch guard also works as a git commit hook, and protects `Main` where git
ignores case.

In the libraries, constructors refuse a `confidence` or `source` off the
ladder, and leaves need a `source`. An egress guard stops mock data at an
output point, and test fixtures can be quarantined as `mock`. Several of
these are breaking. Each Breaking entry in the CHANGELOG says what to do.

[ADR-0022](../adr/0022-tiers-enforcement-labels-auditability.md) writes down
how these fit together: enforcement where a block does not make ordinary
work impossible, accurate labels where it would, and auditability for the
rest.

## Before the tag

The blind auditors passed 9 of 9. The self-audit found 23 findings in the
release diff, and 7 more in the gate change, which merged after it. Each
was fixed before the tag, or deferred as a tracked issue. One gap is open:
the audit misses a stub test that claims to be real
([#620](https://github.com/slopstopper/plumb-line/issues/620)).
