# plumb-line 0.11.4 — guards that fail closed

plumb-line 0.11.4 is a patch. Its theme is enforcement that let things
through when it could not decide.

The branch guard read an unset or empty branch as "not protected" and
allowed every edit. It now blocks a code edit when the branch is unknown; a
docs edit is still allowed, as it is on every branch. This is stricter for
adopters: wiring that never set `PLUMBLINE_BRANCH` was allowing everything
and now blocks code edits. The bootstrap skill shows how to set the branch in
a Claude Code hook and how to pass a repo-relative path. It no longer says
the guards work directly as git hooks, because git supplies neither input.

Claude Code treats only exit 2 from a hook as a block. The branch guard
crashed with exit 1 on input it could not read, and the pre-commit gate
exited 1 with no test command, so both let the action through. Both now exit
2.

Two smaller fixes. The conformance tables for HTTP and baselines now fail on
fields their runners do not read, as `cases.json` already did. The JS example
fixtures load under Node.

Blind validation passed 6/6. The self-audit found an older hole that the
branch-guard fix had kept: a config key could override the branch. That is
fixed. Review turned up
more differences between the JS and Python twins of each guard. They are
filed for 0.12.0, where a shared test table (#475) is the planned fix. The
record of an outside user's audit is now in `docs/dogfood.md`.
