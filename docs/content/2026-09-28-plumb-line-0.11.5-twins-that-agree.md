# plumb-line 0.11.5 — twins that agree

plumb-line 0.11.5 is a patch. Each of its three hooks (the branch guard,
the boundary guard and the pre-commit gate) ships as a JavaScript twin and a
Python twin that are meant to behave identically. This release tests that.

One table, `adapters/hook-cases.json`, now says what each hook does with a
given input, environment and config, and both twins run every row. Building
it found places where the twins split, and places where a guard let
something through when it could not decide. The JS gate passed `test -n ""`.
A gate runner returning `1` passed. An unmapped payload passed the boundary
guard. A branch named `HEAD` or `main ` counted as unprotected. Each now
blocks, in both twins.

This is stricter for adopters. A config key neither guard reads, a
snake_case key, or an environment value that is not valid UTF-8 now blocks
with a reason naming it. The CHANGELOG lists each change and names each
loosening.

One split is left on purpose. JSON with a number of more than 4,300 digits,
or nesting from about 1,000 levels on Python 3.11 (deeper on later
versions), hits a Python runtime limit and blocks there, while JS judges
it. Copying that limit into JS would make an accident part of the contract,
so it is recorded as waived.

Blind validation found every planted violation. One auditor also confirmed
a real violation in a fixture meant to be clean: its service replaced a
measured confidence with a flat 0.8. The fixture was fixed and passed two
re-runs. The self-audit found two more twin splits that no row had covered,
one of them an older hole where the Python branch guard allowed a code file
outside `docs/`. Both were fixed before this release.
